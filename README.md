# Виджет чат-ассистента AvangardAI

Окно чата с ассистентом для сайта. Один JavaScript-файл `avai-chat.js` подключается одним тегом
`<script>` и рисует кнопку чата в углу страницы.

- **Веб-компонент `<avai-chat>` в Shadow DOM.** Стили сайта на виджет не действуют, стили виджета —
  на сайт. Работает рядом с любым фреймворком (Angular, React/Next.js, без фреймворка).
- **Один файл, без зависимостей в рантайме.** Ничего не догружает: ни скриптов, ни шрифтов, ни
  картинок. Совместим со строгим CSP — без `unsafe-inline` и `unsafe-eval`.
- **Без кода под конкретный сайт.** Всё настраивается атрибутами, CSS-переменными и JS API, а для
  своего дизайна исходники в комплекте: интерфейс отделён от логики.

Сервер чата — API шлюза AvangardAI, `https://chat-gateway.avangardai.ru`. Его документация:
**https://chat-gateway.avangardai.ru/docs**.

## Быстрый старт

Положите `avai-chat.js` на свой сайт (или CDN) и добавьте тег в шаблон страницы:

```html
<script src="/avai-chat.js" defer
        data-api="https://chat-gateway.avangardai.ru/v1"
        data-tenant="<имя подключения>"
        data-title="Помощник"
        data-greeting="Здравствуйте! Чем помочь?"
        data-consent-url="https://<ссылка на согласие на обработку ПД>"></script>
```

- `data-tenant` — имя подключения, его выдаём мы. Без него виджет не запускается.
- `data-api` — адрес API. Обязателен, когда файл лежит не на домене шлюза (обычный случай).
- Сайт должен быть в списке разрешённых для подключения — пришлите нам адреса (с протоколом, без
  слеша в конце), включая тестовые. С других сайтов шлюз отвечает `403`.
- Адрес шлюза добавьте в `connect-src` CSP сайта (подробнее — [Требования к сайту](#требования-к-сайту)).

Виджет сам создаёт `<avai-chat>` в конце `<body>`. Если такой тег уже есть в разметке (например, со
своим логотипом в слоте), использует его.

Локально виджет проверяется на моке шлюза (`npm run dev`, см. [Свой дизайн и сборка](#свой-дизайн-и-сборка)).
Боевой шлюз пускает только сайты из списка подключения — для проверки на настоящем шлюзе пришлите
адрес своего тестового стенда.

## Как устроено

```
страница сайта
 └─ <script src="avai-chat.js">  ── читает data-*, window.AvaiChatConfig, очередь window.AvaiChat
     ├─ src/core   логика без интерфейса: сессия, отправка, повторы, лента, история, хуки
     │    └─ HTTPS (fetch) ──► API шлюза /v1 ──► ассистент
     └─ src/ui     веб-компонент <avai-chat> на Lit: только рисует состояние ядра
```

- Пока посетитель ничего не написал, виджет в шлюз не ходит: ни сессии, ни диалога.
- Ответы приходят долгим опросом ленты событий: запрос висит до 25 с и возвращается, как только
  есть новое. WebSocket не нужен.
- Состояние (id диалога, курсор ленты, последние 200 сообщений) кэшируется в `localStorage` для
  мгновенного показа; источник истины — шлюз. Свои сообщения посетителя пишутся туда в том виде,
  в каком ушли в шлюз (после `beforeSend`), ответы ассистента — после `afterReceive`; неочищенный
  текст в браузере не хранится. Токен сессии — только в памяти, cookie не отправляются.
- Открытые вкладки синхронизируются между собой. Без `localStorage` (приватный режим) виджет
  работает, но посетитель новый при каждой загрузке страницы.

## Настройки

### Атрибуты тега

| Атрибут | Назначение | По умолчанию |
|---|---|---|
| `data-tenant` | имя подключения (`tenant` в `POST /v1/sessions`) | **обязателен** |
| `data-api` | адрес API с версией | origin файла виджета + `/v1` |
| `data-title` | заголовок в шапке | «Ассистент» |
| `data-greeting` | приветствие первым сообщением; в историю и в шлюз не попадает | нет |
| `data-consent-url` | ссылка на согласие на обработку ПД; пока посетитель не принял, отправка закрыта. Принятие запоминается; сменится адрес — спросим снова | нет |
| `data-quick-replies` | готовые вопросы через `\|`: `Как сменить тариф? \| Подключить интернет` — кнопки под приветствием, пока посетитель ничего не написал | нет |
| `data-teaser` | подсказка-пузырь у закрытой кнопки через 3 с («Есть вопрос? Спросите ассистента»). Закрыл или открыл чат — больше не показывается | нет |
| `data-auto-open` | открыть через N секунд, один раз на браузер; в полноэкранном (мобильном) режиме не срабатывает | выключено |
| `data-position` | `right` или `left` | `right` |
| `data-ai-avatar` | URL аватара ассистента; хост картинки нужен в `img-src` CSP | нет |
| `data-attachments` | `false` — без вложений (скрепки, вставки из буфера, перетаскивания) | включены |
| `data-rating` | `false` — не показывать запросы оценки диалога | показываются |
| `data-sound` | `false` — без звука нового сообщения (звучит, только когда окно закрыто или вкладка скрыта) | включён |
| `data-title-notify` | `false` — не мигать заголовком вкладки при новом сообщении | мигает |
| `data-branding` | `false` — скрыть подпись «Работает на AvangardAI» под полем ввода | показывается |
| `data-require-hooks` | `true` — без хуков маскирования сообщения не отправляются и не показываются (см. [хуки](#хуки-маскирование-персональных-данных)) | `false` |
| `data-poll-wait` | сколько секунд держать запрос ленты, 0–25; `0` — обычный опрос раз в 3 с | `25` |
| `data-proactive` | JSON-массив правил приглашений; удобнее через `configure()` (см. [приглашения](#проактивные-приглашения)) | нет |
| `data-operator-name`, `data-operator-avatar` | подпись и аватар оператора (сообщения с ролью `operator`) | «Оператор» |

### Объект `window.AvaiChatConfig`

Те же настройки в camelCase (`consentUrl`, `quickReplies`, `requireHooks`…) можно задать объектом
до загрузки файла — удобно, когда тег вставляет фреймворк. Хуки и тексты — только так или через
`configure()`. Приоритет: `configure()` > `window.AvaiChatConfig` > `data-*`.

```js
window.AvaiChatConfig = {
  api: 'https://chat-gateway.avangardai.ru/v1',
  tenant: '<имя подключения>',
  title: 'Помощник',
  texts: { inputPlaceholder: 'Спросите что-нибудь' },
};
```

### Next.js

Подключать один раз на всё приложение — в `_app`/`_document` (pages router) или корневом `layout`
(app router):

```tsx
import Script from 'next/script';
<Script src="/avai-chat.js" strategy="afterInteractive"
        data-api="https://chat-gateway.avangardai.ru/v1" data-tenant="<имя>" data-title="Помощник" />
```

Виджет живёт в `<body>` вне корня React и переживает переходы между страницами. Если передаёте в
контекст раздел сайта, обновляйте его при смене маршрута: `AvaiChat.setContext({ page: router.asPath })`.

### Angular

Тегом в `index.html` или через `angular.json → scripts`. Если загружен zone.js, виджет сам запускает
таймеры и запросы вне зоны Angular (`Zone.root`), поэтому опрос не вызывает проверку изменений во
всём приложении. Обработчики `AvaiChat.on(...)` тоже вызываются вне зоны: меняете в них состояние
компонентов — оборачивайте в `ngZone.run(...)`.

## JS API `window.AvaiChat`

| Вызов | Что делает |
|---|---|
| `open()`, `close()`, `toggle()`, `isOpen` | окно чата |
| `setContext({ключ: значение})` | сведения о странице или посетителе (раздел, регион, авторизован ли); добавляются к текущим и уходят полем `context` с каждым сообщением. `setContext(null)` очищает. До 20 ключей, значения — строки до 500 символов: числа и флаги виджет приводит к строке, объекты — к JSON, длинное обрезает. **Хуки маскирования контекст не проходят** — не кладите в него ПД |
| `reset()` | новый посетитель с чистого листа: лента и кэш очищаются, `visitor_token` забывается, согласие на обработку ПД спрашивается снова; следующее сообщение откроет новую сессию и новый диалог. Вызывайте при выходе пользователя из аккаунта — следующий человек за тем же браузером не увидит чужих диалогов. Кнопки «Новый чат» у посетителя нет |
| `on(event, fn)` → функция отписки; `off(event, fn)` | события, см. ниже |
| `configure({...})` | хуки, тексты и любые настройки из таблицы атрибутов. `api`, `tenant` и `pollWait` применяются, только если вызов попал в очередь до загрузки; позже — предупреждение в консоли |
| `push([метод, ...аргументы])` | то же, что вызов метода; нужен для очереди |
| `destroy()` | убрать виджет со страницы |
| `version` | версия файла |

**События `on()`:**

| Событие | Данные |
|---|---|
| `ready` | виджет загружен (на `document` ещё приходит `avai-chat:ready`) |
| `open`, `close` | окно открыто или закрыто |
| `message` | `{direction: 'in' \| 'out', sender, id, text, attachments?}`; у исходящих `text` — уже после `beforeSend`, то есть то, что ушло в шлюз; вложения — `[{name, mimeType}]`, без содержимого |
| `error` | `{code, message, status?}`: коды шлюза (`unauthorized`, `forbidden`, `rate_limited`, `conversation_closed`, `file_too_large`…) и свои — `before_send_failed`, `after_receive_failed`, `network`, `timeout` |
| `rating` | `{messageId, rating}` — посетитель оценил диалог |
| `proactive` | `{id, action: 'shown' \| 'opened' \| 'dismissed'}` — для аналитики приглашений |

### Вызовы до загрузки

Встроенный скрипт-заглушка потребовал бы `unsafe-inline` в CSP, поэтому очередь — массив, как
`dataLayer` у счётчиков. Код сайта в своём бандле может писать до загрузки виджета:

```js
(window.AvaiChat = window.AvaiChat || []).push(['setContext', { region: 'Москва' }]);
window.AvaiChat.push(['open']);
```

После загрузки виджет выполнит очередь по порядку и заменит массив объектом API;
`AvaiChat.push([...])` продолжит работать.

## Хуки: маскирование персональных данных

Хуки — функции сайта, через которые проходит текст до отправки и до показа. Обычно ими вычищают
персональные данные (номера карт, паспорта, телефоны) своим сервисом маскирования.

```js
AvaiChat.configure({
  // перед отправкой в API: вернуть очищенный текст
  beforeSend: async (text, { conversationId, context }) => maskedText,
  // перед показом ответа: message — сообщение шлюза целиком (parts, fallback_text), actor — {role, name}
  afterReceive: async (text, { conversationId, context, sender, messageId, message, actor }) => shownText,
  // перед отправкой картинки: вернуть Blob (тот же или изменённый) или null — не отправлять
  beforeAttach: async (blob, { conversationId, context, name }) => blob,
});
```

Все три работают по принципу **fail-closed**: при сбое данные не уходят и не показываются.

- `beforeSend` бросил ошибку, вернул не строку или пустую строку, не ответил за 5 с — сообщение не
  уходит, текст остаётся в поле ввода, посетитель видит «Не удалось подготовить сообщение» и кнопку
  «Повторить». Неочищенный текст в API не уходит ни при каком сбое.
- `afterReceive` упал или не ответил — исходный ответ не показывается, вместо него заглушка с
  кнопкой повтора.
- `beforeAttach` — то же для картинок: ошибка, `null` или 5 с без ответа — картинка не уходит.
  Текстовые хуки картинку не очищают; что делать с картинками, стоит согласовать с ИБ.
- Посетитель в своей ленте видит то, что ввёл; в шлюз и при повторной отправке уходит результат
  `beforeSend`.
- `conversationId` — `null`, пока диалог не создан (до первого сообщения). Прежнее имя `chatId`
  оставлено синонимом.
- В `afterReceive` попадает текст частей `text` (или `fallback_text`, если в сообщении есть часть
  незнакомого типа). Служебные фразы шлюза (часть `system`) хук не проходят.
- Хуки, переданные после загрузки, могут опоздать к первым входящим сообщениям. Если это
  недопустимо — `data-require-hooks="true"`: пока хуков нет, отправка закрыта, а входящие ждут.
  Без `beforeAttach` в этом режиме картинку отправить нельзя.

### Части `::part()`

```css
avai-chat::part(launcher) { border-radius: 16px; }

avai-chat::part(message-user) { background: #1d2023; }
```

| Где | Части |
|---|---|

| окно | `panel`, `header`, `title`, `close` (крестик, только в полноэкранном режиме), `notice`, `consent`, `consent-accept`, `branding` |
| лента | `messages`, `message` (все пузыри), `message-user`, `message-bot`, `message-operator`, `author`, `avatar`, `time`, `date`, `message-status`, `message-read` (✓✓), `system`, `typing` |
| ввод | `composer`, `input`, `send`, `counter`, `attach`, `attachment-preview` |
| файлы | `attachment-image`, `attachment-file`, `viewer` (просмотр картинки) |
| оценка | `rating-card`, `rating-like`, `rating-dislike`, `rating-star` |

### Слоты

Когда тег `<avai-chat>` стоит в разметке страницы:

```html
<avai-chat>
  <img slot="logo" src="/logo.svg" alt="">           <!-- логотип в шапке -->
  <svg slot="launcher-icon">…</svg>                  <!-- своя иконка кнопки -->
</avai-chat>
```

### Тексты

Все строки интерфейса — в `src/core/texts.ts`; меняются без пересборки:
`AvaiChat.configure({ texts: { inputPlaceholder: '…', ratingPrompt: '…' } })`.

## Свой дизайн и сборка

Нужен Node.js 20.19+ (проверено на 24).

```bash
npm install
npm run dev        # исходники через Vite + мок шлюза: http://localhost:5173/dev.html
npm run demo       # собранный файл на «враждебной» странице: http://localhost:5180/ (нужен npm run build)
npm test           # юнит-тесты ядра (vitest)
npm run build      # проверка типов → dist/avai-chat.js → dist/core/ (ядро + типы)
```

### Структура

```
    chat.ts           ChatController: отправка, повторы, опрос, история, хуки, события
    transport.ts      HTTP к шлюзу: сессия, заголовки, таймауты, ошибки, Retry-After
    store.ts          localStorage и синхронизация вкладок
    attachments.ts    подготовка картинок (ужатие, EXIF)
    texts.ts          строки интерфейса
    types.ts          типы сообщений и частей

  ui/

    styles.ts         стили (px, CSS-переменные, parts)

    sound.ts          звук нового сообщения

tests/                юнит-тесты

```

### Как переделать дизайн

1. Сначала попробуйте без сборки: CSS-переменные и `::part()` покрывают цвета, шрифты, размеры и
   скругления.
2. Глубже — правьте `src/ui/`: `chat-element.ts` (разметка) и `styles.ts` (стили). Ядро трогать не
   нужно: интерфейс только рисует `controller.state` и вызывает методы ядра.
3. `npm run dev` — правки видны сразу на моке; `npm run build` — готовый `dist/avai-chat.js`.

Имя тега — константа `TAG` в `src/ui/chat-element.ts` (префикс продукта: короткие префиксы сайта
часто заняты его собственными компонентами).

### Свой интерфейс на ядре

Если виджет не подходит совсем, можно взять только ядро `dist/core/avai-chat-core.js` (ES-модуль с
типами): отправка, повторы, лента, история, хуки — без интерфейса.

```ts
import { ChatController, Store, Transport } from './avai-chat-core.js';

const store = new Store('<имя подключения>');
const chat = new ChatController({
  transport: new Transport({ api: 'https://chat-gateway.avangardai.ru/v1', tenant: '<имя>', visitor: store.visitor }),
  store,
  hooks: { beforeSend: async (t) => t },
});
chat.subscribe((e) => { if (e.type === 'change') render(chat.state); });
chat.setActive(true);          // окно открыто: опрашивать ленту
await chat.send('Здравствуйте');
```

Или напишите клиент сами по документации API: https://chat-gateway.avangardai.ru/docs.

### Мок шлюза

`npm run dev` и `npm run demo` поднимают мок, повторяющий браузерную часть API (включая ошибки и
CORS). Команды пишутся в чат: `/help` — список. Например: `/slow` (ответ через 25 с), `/many`
(7 сообщений), `/md` (разметка), `/html` (теги в ответе), `/card` (часть незнакомого типа),
`/image`, `/doc` (файлы ассистента), `/rate`, `/stars` (оценка), `/503` (ассистент недоступен),
`/401`, `/403`, `/422`, `/429`, `/close`, `/expire` (устаревший курсор).

Демо-страница `demo/index.html` нарочно враждебная: `html{font-size:62.5%}`,
`div:empty{display:none}`, глобальные `*{}` с `!important`, повороты и фильтры, строгий CSP без
`unsafe-*`. `/same-origin` — подключение только с `data-tenant`.

## Требования к сайту

### CSP

| Директива | Что нужно |
|---|---|
| `script-src` | хост файла виджета (лежит на сайте — `'self'`). `unsafe-inline` и `unsafe-eval` не нужны |
| `connect-src` | `https://chat-gateway.avangardai.ru` (или ваш прокси шлюза) и сервис маскирования, если хуки ходят в него из браузера |
| `img-src` | `data:` (превью своих картинок) и `blob:` (картинки ассистента); плюс хост аватаров, если заданы. С `data-attachments="false"` и без аватаров — ничего |
| `style-src`, `font-src` | ничего: стили — через `adoptedStyleSheets` и CSSOM, шрифтов виджет не грузит |
| `trusted-types` | если включены Trusted Types (`require-trusted-types-for 'script'`) — разрешить политику `lit-html` |

### Сеть

- Запросы идут на другой домен, поэтому у каждого — preflight `OPTIONS`. Прокси и WAF сайта на
  пути должны пропускать `OPTIONS` и заголовок `Authorization`.
- Если шлюз проксируется под доменом сайта (same-origin), preflight не нужен вовсе; тогда `data-api`
  указывает на прокси.
- Запрос ленты держится до 25 с — таймауты прокси должны быть больше.

### Браузеры

Актуальные Chrome, Edge, Firefox, Яндекс Браузер; Safari 16.4+ (macOS, iOS). Сборка — ES2021.
На узких экранах (до 480 px) и на телефоне в альбомной ориентации окно разворачивается на весь экран,
прокрутка страницы под ним блокируется; открытая клавиатура iOS не закрывает поле ввода.

Файл собирается из этого репозитория:


|---|---|

## Возможности: вложения, приглашения, оценка

### Картинки

Включены по умолчанию, выключаются `data-attachments="false"`.

- **От посетителя** — одна картинка на сообщение, с текстом или без (скрепка, вставка из буфера,
  перетаскивание). Перед отправкой картинка перерисовывается: PNG — в PNG без потерь, остальное, что
  открывает браузер (JPEG, HEIC в Safari, WebP), — в JPEG; сторона — не больше 2048 px. Метаданные
  (EXIF: геолокация, модель телефона) при этом не уходят. GIF — как есть, чтобы не пропала анимация. Имя файла на шлюз не уходит — в нём бывают ПД
  («Паспорт_Иванов.jpg»); посетитель в ленте видит своё имя. Предел — 15 МБ после ужатия.
- **От ассистента** — картинки в ленте, остальные файлы — плашкой с именем и размером, скачиваются
  по клику. Клик по картинке открывает просмотр поверх окна.
- Файлы виджет забирает с токеном в заголовке и показывает через `blob:` URL — токен не попадает в
  адрес. Шлюз хранит картинку посетителя, только пока не передал её ассистенту; потом в истории
  остаётся превью из кэша браузера или плашка с именем.

### Проактивные приглашения

Заготовленное сообщение по правилу — как «активные приглашения» в онлайн-консультантах. Пока
посетитель не ответил, в шлюз ничего не уходит.

```js
(window.AvaiChat = window.AvaiChat || []).push(['configure', {
  proactive: [
    { id: 'tariffs-30s', text: 'Подсказать, какой тариф выбрать?', url: '/tariffs', delay: 30 },
    { id: 'exit', text: 'Уже уходите? Оставьте вопрос — ответим здесь.', exitIntent: true },
    { id: 'esim', text: 'Помочь оформить eSIM?', url: '/^\\/esim/', delay: 5, open: true },
  ],
}]);
```

| Поле | Что значит |
|---|---|
| `id` | ключ правила: показывается **один раз на посетителя** и приходит в контекст его ответа |
| `text` | текст приглашения |
| `url` | на каких страницах: подстрока пути, строка-регулярка (`/^\/tariffs/`) или `RegExp`; без поля — на всех |
| `delay` | через сколько секунд на странице; по умолчанию сразу |
| `exitIntent` | `true` — когда посетитель уводит мышь за верх окна; на телефоне не срабатывает |
| `open` | `true` — сразу открыть чат с этим сообщением; по умолчанию — пузырь у кнопки |

- Не показывается, если чат открыт, уже висит другое приглашение или посетитель сам писал за
  последние 30 минут. На SPA правила перевзводятся при смене адреса.
- Открыл чат — приглашение становится сообщением ассистента. Первый ответ посетителя уходит с
  контекстом `{proactive: id, proactive_text, page}` — ассистент понимает, о чём речь. `page` — адрес
  страницы без query и `#` (в них бывают email и токены).
- Сработавшее приглашение заменяет подсказку `data-teaser`.

### Оценка диалога

Когда спросить оценку, решает ассистент: в ленте приходит часть `rating_request`. Виджет рисует
карточку «Оцените, пожалуйста, наш диалог» (`texts.ratingPrompt`) — «Понравилось / Не понравилось»
или пять звёзд. Одна оценка на запрос, без комментария (в оценку не попадает свободный текст,
маскировать нечего). Оценка из другой вкладки закрывает карточку и здесь. `data-rating="false"` —
не показывать.

## Протокол с шлюзом

Полное описание — https://chat-gateway.avangardai.ru/docs. Коротко, что делает виджет:

1. **Сессия.** `POST /v1/sessions {tenant, visitor_token?}` → `session_token` (на час) и, только у
   нового посетителя, `visitor_token`. `visitor_token` хранится в `localStorage`
   (`avai-chat:<tenant>:visitor`) — по нему посетитель возвращается к своим диалогам. Дальше каждый
   запрос — `Authorization: Bearer <session_token>`; на `401` виджет один раз обновляет сессию и
   повторяет запрос.
2. **Диалог.** Создаётся первым сообщением: `POST /v1/conversations`. `reset()` — новый посетитель и
   новый диалог.
   Диалог закрыт (`409 conversation_closed`) или чужой (`404`) — виджет создаёт новый и повторяет
   отправку.
3. **Отправка.** `POST /v1/conversations/{id}/messages {client_msg_id, parts, context?}` → `201`.
   Ответ ассистента в нём не приходит — только в ленте. Повтор с тем же `client_msg_id` (UUID)
   безопасен: второго сообщения не будет.
4. **Лента.** `GET /v1/conversations/{id}/events?after=<cursor>&wait=25` → `{events, cursor}`. Идёт,
   пока окно открыто и вкладка видна, и в фоне, пока ждём ответа. События: `message.created`,
   `message.updated` (например, оценено), `typing` («печатает»; сразу после отправки виджет показывает его сам, но не дольше 30 с), `read` (✓✓ «прочитано»);
   незнакомые пропускаются.
5. **Части сообщения.** `text` — безопасная разметка; `file` — картинка или файл; `system` — фраза
   шлюза по центру ленты (например, ассистент не смог ответить); `rating_request` — карточка оценки.
   **Часть незнакомого типа показывается как `fallback_text`** — новые типы не ломают виджет.
6. **История.** При первом открытии чата виджет сверяет кэш с `GET /v1/conversations/{id}/messages`.
   Курсор устарел (`410`) — перечитывает историю.

**Ошибки** — RFC 9457, разбор по `code`:

- `401` после повторной сессии, `403`, отказ сессии — «чат временно недоступен», отправка закрыта до
  перезагрузки страницы;
- `422` — сообщение «не отправлено», без повтора; `413`, `415` — «изображение не принято»;
- `429` — ждёт `Retry-After` и отправляет сам;
- `5xx` и обрыв связи — повтор с тем же `client_msg_id` через `Retry-After` (без заголовка — 1, 2, 4,
  8, 16, 30 с) с баннером «пробуем ещё раз»; после шести неудач — «не отправлено» с кнопкой повтора.

**Безопасность ответов.** HTML из ответа не разбирается: всё собирается текстовыми узлами Lit, теги
видны как текст. Разметка — **жирный**, *курсив*, `код`, списки, заголовки, ссылки. Ссылкой
становятся только `http:`, `https:`, `mailto:`, `tel:` (проверка без учёта регистра и после
удаления пробелов и управляющих символов — `javascript:`, `data:` остаются текстом). Сообщения
посетителя — обычный текст. Лимит — 4000 символов, счётчик появляется с 3500.

## Что не поддерживается

- **Вложения посетителя, кроме картинок** — документы, аудио и видео не принимаются.
- **Потоковые ответы** (по словам) и WebSocket/SSE — ответ приходит целиком через долгий опрос.
- **Голос** и звонки.
- **«Печатает» от посетителя** — шлюзу не передаётся.
- **Кнопка «Новый чат»** у посетителя — только `AvaiChat.reset()` со стороны сайта.
- **Комментарий к оценке** — только «нравится / не нравится» или звёзды.
- **Internet Explorer** и Safari до 16.4.
